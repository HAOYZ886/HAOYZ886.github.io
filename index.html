Linux - 使用实时分析工具rtla观测实时

Posted on 2026-04-30 Edited on 2026-05-15 In 原理及实现 Word count in article: 9k Reading time ≈ 33 mins.

什么是rtla

rtla 的全称为 Real-Time Linux Analysis ，它是一个基于 FTrace 的实时分析工具集，已在 Linux 5.17 集成。它与 cyclictest 类似，但不同的是，它能监测出中断响应，以及任务唤醒到任务执行之间的抖动延迟；还能监测系统噪音检验任务的可观测性。

系统噪音：指的是一个任务在可运行期间被强行打断，如被高优先级的线程抢占、IRQ、SoftIRQ、NMI 和 SMI 等。

rtla 背靠 FTrace 的 osnoise 和 timerlat 机制，不仅能量化系统的调度延迟与抖动，更能自动定位产生高延迟的根本原因（如中断屏蔽、长临界区或硬件干扰）。也由此可知，它解决了 cyclictest 只能测“延迟有多大”却无法回答“延迟从哪来”的痛点。

定义与核心特性

rtla 是一个前端工具，它的后端是 FTrace 的 osnoise 和 timerlat ，所以它属于白盒测量。而传统的延迟测试工具（如 cyclictest），则是采用黑盒测量。
cyclictest 的基本实现是：为每个 CPU 新建一个高实时优先级的应用线程，主动调用 nanosleep() 休眠并等待唤醒，通过计算预期唤醒时间与实际唤醒时间的差值，以此得到一个延迟样本。

Linux - 手动注入延迟来观测实时抖动

Posted on 2026-04-25 Edited on 2026-05-03 In 原理及实现 Word count in article: 8.1k Reading time ≈ 30 mins.

前言

根据之前几篇文档的说明可知，RTOS 的确定性来源于项目的需求，而具体的实现是：中断的响应，以及任务的调度和执行完成是否在指定的范围内。
在 Linux 中，

  • 中断的响应快慢，分为以下原因：
    1. 中断是否被关闭（主要），而中断关闭的原因是：
    • 框架/子系统的实现自身要求的，比如 spin_lock_irq()
    • 进入中断上下文（包括 NMI ）时关闭
    1. 硬件延迟（SMI）导致（次要），而导致此的原因是：
    • 如 ARM64 架构，由于 Linux 运行在 EL1 ，则它无法感知 EL2/EL3 ，当陷入更高级运行等级时，内核处于停止状态。
    • 如 X86 架构，BIOS/固件执行相关操作，CPU 无法屏蔽，只能等待完成。
  • 任务的响应快慢，分为以下原因：
    1. 抢占是否被关闭（主要），而抢占关闭的原因是：
    • 框架/子系统的实现自身要求的，比如 spin_lock_irq()
    1. 在就绪队列中的任务，或当前任务的实时优先级比指定调度的任务优先级更高
    2. 实时仲裁（Linux机制，间接导致）。比如在 1 秒时间内要求 0.95 秒跑实时任务，其余时间跑非实时任务。高优先级任务（优先级大于或等于你想要响应的任务）占满 0.95 秒，触发实时仲裁，你想要响应的任务也会被延后至少 0.05 秒得到调度。
    3. 优先级反转。比如低优先级的线程持有锁并正在执行，但是此时高优先级的线程抢占了执行该低优先级的线程的 CPU ，而且尝试获取低优先级的线程已持有的锁，但获取不了从而让出执行权，只能等待低优先级的线程释放锁。
    4. 硬件延迟（SMI）导致

Linux-可抢占内核的原理与实践

Posted on 2026-04-09 Edited on 2026-04-11 In 原理及实现 Word count in article: 4.9k Reading time ≈ 18 mins.

可抢占内核和非可抢占内核是什么

可抢占内核与非可抢占内核的区别在于内核态代码是否允许被强制打断，这直接影响系统在低延迟响应与高吞吐量之间的取舍。

定义与典型场景

  1. 非可抢占内核
    • 当一个进程因系统调用或中断进入内核态运行时，该进程独占 CPU 直至内核态执行完毕（返回用户态）、主动调用调度器让出 CPU，或在显式的抢占点检查调度。即使有更高优先级的就绪任务，也无法抢占当前内核态任务的执行权。
    • 典型场景：服务器、高性能计算集群。这些场景更关注单位时间内处理的任务总量（吞吐量），而非单个任务的响应延迟。
  2. 可抢占内核
    • 内核态代码执行路径中，除了持有自旋锁或显式禁用抢占的极短临界区外，均可被高优先级任务强制打断。调度器可以随时剥夺当前内核态任务的执行权，切换至更高优先级的任务。
    • 典型场景：桌面系统、软实时嵌入式系统、多媒体处理。这些场景要求系统对交互事件或外部中断有较快的响应速度，即使牺牲部分吞吐量。

实时操作系统原理浅析

Posted on 2026-04-07 Edited on 2026-04-12 In 原理及实现 Word count in article: 2.7k Reading time ≈ 10 mins.

什么是实时操作系统

实时操作系统的核心在于确定性——在严格的时间限制内完成任务响应，并且在可预测的时间内完成。
通用操作系统追求高吞吐量，实时操作系统追求时间可预测，这是两者设计目标的根本区别。

实时操作系统与通用操作系统的区别

操作系统按时间约束的保证能力分为通用操作系统（GPOS）和实时操作系统（RTOS）。区别不在运算速度，而在对时间约束的保证能力。

Linux - hwspinlock框架解析

Posted on 2026-03-23 In 原理及实现 Word count in article: 1.9k Reading time ≈ 7 mins.

前言

hwspinlock 名为硬件自旋锁。已知互斥锁的持有单位是进程/线程，自旋锁的持有单位是 CPU 的 Core ，它们统一特征是都在同一个操作系统内跑的。而硬件自旋锁的持有单位是跑不同操作系统/裸机的 CPUs 。需要硬件自旋锁的原因也很简单，就是保证共享资源的数据一致性，只不过范围更广，在不同操作系统/裸机的 CPUs 的范围内。总得来说，硬件自旋锁是一个跨系统的硬件同步机制。

一个简单的实例就是 ARM64 A55 跑 Linux ，另一个 Risc-V E907 跑 FreeRTOS ，它们之间需要一个共享内存进行数据共享，这就需要确认一个临界区来保证该共享内存的数据一致性。
