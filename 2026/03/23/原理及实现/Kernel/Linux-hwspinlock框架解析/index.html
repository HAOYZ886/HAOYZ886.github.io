Linux - hwspinlock框架解析

Posted on 2026-03-23 In 原理及实现 Word count in article: 1.9k Reading time ≈ 7 mins.

前言

hwspinlock 名为硬件自旋锁。已知互斥锁的持有单位是进程/线程，自旋锁的持有单位是 CPU 的 Core ，它们统一特征是都在同一个操作系统内跑的。而硬件自旋锁的持有单位是跑不同操作系统/裸机的 CPUs 。需要硬件自旋锁的原因也很简单，就是保证共享资源的数据一致性，只不过范围更广，在不同操作系统/裸机的 CPUs 的范围内。总得来说，硬件自旋锁是一个跨系统的硬件同步机制。

一个简单的实例就是 ARM64 A55 跑 Linux ，另一个 Risc-V E907 跑 FreeRTOS ，它们之间需要一个共享内存进行数据共享，这就需要确认一个临界区来保证该共享内存的数据一致性。

相关硬件设计

硬件自旋锁硬件模块里有多个硬件自旋锁，一般是 32 个，且仅有两种状态：被锁和未被锁。以下是它的硬件逻辑结构例子：

简单来说，在对 HW-Spinlock 的 AHB 总线 dereset ，并开启对应的时钟，CPU 通过 MMIO 访问 HW-Spinlock 的寄存器，尝试去持有锁和释放锁。

另外，HW-Spinlock 模块可以支持发送中断的能力，这是可选的。一般来说是当锁被释放后发送 IRQ ，通知可以去持有锁。

但是在 Linux 5.10，还未看见框架支持该功能，可能需要自行实现。

框架结构体

HW-Spinlock 框架提供了三个结构体：struct hwspinlock_device、struct hwspinlock和 struct hwspinlock_ops。

  • struct hwspinlock_device：是 HW-Spinlock 设备描述符，记录锁的资源和回调函数集。
  • struct hwspinlock：是一个锁实例，consumer 需要获取它才能获取和释放锁。
  • struct hwspinlock_ops：是一个回调函数集，consumer 需要通过 HW-Spinlock 框架调用回调函数去获取和释放锁。
