NO_HZ_FULL

目前 Linux 支持三种调度定时器策略：

  1. CONFIG_HZ_PERIODIC ：一直周期性地触发调度定时器，不管 CPU 是否处于 IDLE 状态。
  2. CONFIG_NO_HZ_IDLE ：除了 CPU 处于 IDLE 状态，一直周期性地触发调度定时器。
  3. CONFIG_NO_HZ_FULL ：一直周期性地触发调度定时器，除了 CPU 处于 IDLE 状态，以及它的调度就绪队列仅有一个 task 。

如果选择 CONFIG_NO_HZ_FULL ，则一个且仅有一个实时任务绑定在一个 CPU 运行时，不会触发调度定时器中断。
但需要添加内核参数 nohz_full 指定哪个，或哪些 CPU 去使用这个策略。

测试实时抖动

在压力测试需要用到以下命令：

用途：对系统进行虚拟内存压力测试，并限制在特定的CPU核心上运行，持续24小时。

参数说明：

  • **--vm 1**：启动 1 个虚拟内存压力测试工作进程。每个实例都会分配内存并进行压力测试。
  • **--vm-bytes 50%**：指定虚拟内存压力测试进程总共将占用系统可用内存的 50%。根据工具说明，如果是1个进程共享50%的内存，则每个进程大约占用 6.25% 的可用内存。
  • **--taskset 3**：设置 CPU 亲和性，将压力测试进程绑定到 CPU 3 上运行，使其只在指定的 CPU 核心上施加压力。
  • **--timeout 24h**：设置压力测试的持续时间为 24 小时。

用途：对系统进行网络套接字压力测试，同样限制在特定的CPU核心上运行，持续24小时。

参数说明：

  • **--sock 1**：启动 1 个套接字压力测试进程，用于锻炼网络子和系统内核的套接字接口。
  • **--taskset 3**：设置 CPU 亲和性，将压力测试进程绑定到 CPU 3 上运行。
  • **--timeout 24h**：设置压力测试的持续时间为 24 小时。

用途：对系统进行网络套接字压力测试，同样限制在特定的CPU核心上运行，持续24小时。

参数说明：

  • **stress-ng**：调用 stress-ng 压力测试工具。
  • **--io 1**：启动 1 个 IO 压力测试进程，用于锻炼 Block 子系统。
  • **--taskset 3**：设置 CPU 亲和性，将压力测试进程绑定到 CPU 3 上运行。
  • **--timeout 24h**：设置压力测试的持续时间为 24 小时。
  • **&**：将命令放入后台运行。

用途：对系统进行高强度的 CPU 计算压力测试，结合高频的定时器事件来增加调度负载，限制在特定的CPU核心上运行，持续24小时。

参数说明：

  • **-c 36**：启动 36 个 CPU 压力测试工作线程，对 CPU 施加负载。
  • **--taskset 3**：设置 CPU 亲和性，将压力测试进程绑定到 CPU 3 上运行。
  • **--cpu-method fft**：指定 CPU 压力测试使用的方法为 fft（快速傅里叶变换，Fast Fourier Transform）。这是一种计算密集型的算法，非常适合用于 CPU 压力测试。
  • **--timerfd-freq 1000000**：设置定时器的频率为 1000000（即 1 MHz）。根据参考资料，1000000 纳秒等于 1 毫秒，此参数调整了负载任务的调度频率，使其更频繁地进行计算和中断，可以在每秒产生大量的定时器事件。
  • **--timeout 24h**：设置压力测试的持续时间为 24 小时。

下一步，使用命令cyclictest测试实时抖动：

  • **taskset -c 3**：这是一个 CPU 亲和性设置命令，用于将后续的 cyclictest 进程强制绑定到 CPU 核心 3 上运行。这样可以避免进程在多核之间迁移带来的缓存失效和调度延迟，保证测试的稳定性。
  • **cyclictest**：高精度测试程序，用于测量和分析 Linux 系统的实时延迟性能。
  • **-t 1**：指定测试的线程数量为 1。
  • **-c 1**：选择时钟类型。1 代表 CLOCK_REALTIME（默认 0 代表 CLOCK_MONOTONIC）。
  • **-m**（--mlockall）：锁定当前和接下来的内存，防止发生 swap（换页），避免因为内存交换而影响实时测试的准确性。
  • **--policy=fifo**：设定测量线程的调度策略为 FIFO（先进先出）。这是一种实时调度策略，适用于对延迟要求严格的实时任务。
  • **-Sp 99**：
  • -S（--smp）：标准 SMP 架构测试，使所有线程使用相同的参数。
  • p 99（--prio=99）：设置测试线程的优先级为 99（实时优先级的最高值）。
  • **-D 24h**（--duration=TIME）：指定测试的持续时间为 24 小时（h 代表小时）。
  • **-N**（--nsecs）：测试结果使用精度更高的 纳秒 显示（默认单位是微秒 us）。
