MIPI-DSI的基本概念

总线概述

MIPI-DSI 是由 MIPI 联盟开发的一种标准的输出视频流总线规范，规定了主机与外围设备之间的连接标准，如 SoC 与显示屏之间的连接。DSI 全称是 Display Serial Interface ，顾名思义，该规范是把主机的数据按位串行发送到外围设备。
该总线还额外基于 DPI-2（Display Pixel Interface）、DBI-2（Display Bus Interface）和 DCS（Display Command Set）标准，其中 DCS 是一种命令标准。该总线能发送命令或像素数据到外围设备，也能从外围设备中获取相关信息。它有两种传输模式，分别是 LP（Low Power）和 HS（High Speed）。

就目前公认的使用情况来说，MIPI-DSI 的物理层一般是 D-PHY ，使用半双工通信，见以下概念图：

由此可知，主机与外围设备之间连接的通道有：一条时钟通道和四条数据通道，而且这些串行通道必须是差分的。

为什么 MIPI-DSI 是差分总线？见 D-PHY的电平信号 。

协议栈

概述

与多数的高速串行总线无异，像 SATA 、PCIe 和网络协议栈（网线也是串行差分总线）一样， MIPI-DSI 被分为 4 层：

见以下对各层的简述。

  1. 应用层（Application Layer）：
    • 发送端：处理来自 DPU/DE/LCDIF 的原始像素数据流，包括根据时序的水平/垂直消隐区和 Sync 信号，生成一系列的数据包的数据源。另外，有些 SOC 厂商的 DSI 主控（DSI Host Controller）支持用户基于规范可自定义发送数据包。以 I.MX8MP 为例，它提供 SFR（Special Frame Register）机制，提供一系列的寄存器接口。用户配置好与 SFR 机制相关的寄存器后即可使用（大多数与自身 MIPI-DSI 的时钟相关，如 EscClk（Escape Clock）和 BitClk ）。多数情况来说，该机制用于 DSI 主控作 DSI Master ，发送 Panel-Init-Sequence 到 DSI 屏幕（DSI Slave）。

      Panel-Init-Sequence 是一组在启用 DSI 屏幕前的配置命令，一部分是 MIPI 联盟根据 DCS 标准定义的基础命令，一部分是屏幕厂商根据基于 DCS 标准定义的私有命令。

    • 接收端：接收来自协议层（Packet Based Layer）的数据包数据本体。对于 DSI 屏幕，则是根据 DSI Master 发送的像素数据、消隐信息和 Sync 信息，根据自身的运行逻辑去显示画面。当然，在正式使能屏幕前，必要时需要根据 DSI Master 发送的 Panel-Init-Sequence 去配置自身的运行逻辑。
  2. 协议层（Packet Based Layer）：
    • 发送端：接收来自应用层的原始数据，根据数据的类型和长度，区分短数据包和长数据包，并生成 ECC 和 CRC 校验和（短数据包不用生成校验和）。接着添加包头和包尾，然后把该数据包按字节下发到链路层。
    • 接收端：按字节接收来自链路层的数据包，根据数据的类型和长度，区分短数据包和长数据包，根据数据包的包头生成 ECC ，根据数据包的数据本体生成校验和（仅限长数据包），检查数据包的 ECC 以及校验和是否一致。如果不一致，则表示传输出现错误。
  3. 链路层（Lane Management Layer）：
    • 发送端：接收来自协议层的数据包，按字节按顺序分发到各个 Lane （称之为数据流）。Lane 的数量取决于用户或接收端的带宽需求。在 LP 模式下，发送字节数据流的时钟频率取决于 Escape Clock ；在 HS 模式下，则取决于 Byte Clock 。这两种时钟都基于 Bit Clock 生成。
    • 接收端：根据用户使能的 Lane(s)，按字节接收来自物理层的数据流。把字节数据组合成数据包，并发送到协议层。
  4. 物理层（PHY Layer）：
    • 发送端：接收各 Lane(s) 的字节数据流，并按 Bit 串行化，根据 LP 或 HS 模式，以 LSB 的形式发送 Bit 数据流发送到 DSI Slave 。 Data Lane 从 LP 切换到 HS 模式后，发送数据前需要发送 SoT (Start of Transmission)信号，用于对接收端的 Clock Lane 和 Data Lane 之间的校准；从 HS 切换到 LP 模式前，发送数据接收后需要发送 EoT(End of Transmission) ，通知接收端数据传输完成。在 HS 模式下，需要驱动 Clk Lane ，生成 DDR 时钟频率发送给接收端用于数据获取。另外，发送端和接收端的 Lane 的电气属性要一致（但多数情况下是遵循 MIPI D-PHY 规范的标准属性）。
    • 接收端：根据 Data Lane(s) ，接收来自 DSI Master 的 Bit 数据流。把 Bit 数据流反串行化，即组合为字节数据流，继续按 Lane(s) 发送到链路层。接收端通过 LP-RX ，根据 D-PHY 规范定义的 Contention 电压等级和厂商对该端设定的电压等级，确认发送端是从 LP 切换到 HS 模式，还是从 HS 切换到 LP 模式下发送数据。接收端以此方式接收 Bit 数据流。

下面将各层详细说明。

结合实际去理解协议栈

关于 MIPI-DSI 协议栈，这里使用对 MIPI-DSI 硬件和软件的实现去解释。如果调试一款 MIPI 屏幕，最基本的，是需要获取到它的时序参数以及它的面板初始化序列（Panel Init Sequence）。其中，面板初始化序列是在显示图像之前发送到 MIPI 屏幕的 IC ，而且必须在 LP 模式下传输。序列完成后，即可在 HS 模式下，根据屏幕规定的时序去显示图像。

见以下对各个组件的解释：

  • APB_IF 和 DISPCON_IF ：从 MIPI-DSI 规范的定义上理解，它们属于应用层。DISPCON_IF 的 Input 端是 DPU/DE/LCDIF ，把原始像素数据和信号转换为 MIPI-DSI 的数据源。APB_IF 是 DSI 主控的 SFR 模块，接收并发送来自用户的自定义数据包。
  • PH_FIFO_X 和 PL_FIFO_X ：我们仅关注 PH_FIFO_SFR 、PL_FIFO_SFR 、PH_FIFO_MD 和 PL_FIFO_MD 。用于缓存来自应用层的数据源。注意，短数据包存储在 PH_FIFO_X 。
  • PH_ARBITER 、PL_MAX 、ECC 和 CRC：它们属于协议层。对于短数据包，仅经过 ECC 组件；对于长数据包，必须经过 ECC 组件（ 4 字节包头）和 CRC（数据本体）组件。
  • Rx_Buf 和 LANE_DISTRIBUTER ：它们属于链路层。LANE_DISTRIBUTER 把数据包按字节按顺序分发到各个已使能的 Lane 。

DSI的Command模式和Video模式

在 MIPI-DSI 的规范中，定义了两种模式，分别是 Command 和 Video 模式。

Command模式

Command 模式对应 DBI（Display-Bus-Interface）标准，用在含有 Framebuffer 的外围设备。该模式多数用在单片机，比如 STM32 单片机驱动 MCU 屏。
当画面有变化时，DSI 主控将像素数据发给屏幕。主控只有在画面需要更改的时候发送像素数据，画面不变化的时候屏幕驱动芯片从自己内部 Buffer 里面提取数据显示，Command 模式下需要双向数据接口。
一般该模式的屏幕尺寸和分辨率不大，一般用在单片机等低端领域。以下是 Command 模式概念图：

Video模式

video 模式对应 DPI（Display-Pixel-Interface）标准，没有 Framebuffer，需要主控一直发送数据到外围设备。该模式和 RGB 接口屏幕类似，但没有 Vsync 、Hsync 和 DE 等信号发送同步信息。这些控制信号和像素数据以报文的形式，通过 Data Lane 发送到屏幕。

本文档仅关注 Video 模式，所提到的 DSI 主控遵循 DPI 标准。既能在 LP 模式下发送和接收数据（仅在 Data Lane0），也能在 HS 模式下发送数据。

对于 SoC ，它的 D-PHY 能连接 DSI 屏幕和 CSI 摄像头，取决于 D-PHY 的上层是 DSI 芯片还是 CSI 芯片。以下是基于 D-PHY 规范的基本架构：

从中得知：

  1. 规定 D-PHY 有一条 Clock Lane 和四条 Data Lane 。
  2. 每条 Lane 都支持 TX 和 RX 。
  3. 每条 Lane 都支持 LP 模式和 HS 模式。
  4. DSI Master 依赖自己的 PLL 时钟频率来发送数据（注意 CLK_J 和 CLK_Q ）。
  5. DSI Slave 依赖对方的时钟频率来接收数据（注意 Clk Timer ）。

另外，D-PHY 规范规定，只能在 Data Lane0 在 LP 模式下发送和接收命令。结合上图得知 MASTER DATA0 和 MASTER DATA1,2,3 的结构不同。

本文档只关注 MIPI-DSI ，则对于 DSI Master 的 D-PHY ：

  1. 在 HS 模式，Clock Lane 和 Data Lane(s) 仅支持 TX 。
  2. 在 LP 模式，仅有 Data Lane0 支持 TX 和 RX 。

在 D-PHY 的 Common 组件中，PLL 是用于生成 MIPI-DSI 时钟，称之为 Bit Clock 。该时钟频率是在 HS 模式下发送 bit 数据流的关键。在 D-PHY 的规范中，指定用 DDR 方式发送数据，即双边沿数据采集，即实际发送的时钟频率是 BitClk/2 。注意 PLL 组件引出的 CLK_J 和 CLK_Q 通道，在 HS 模式，MASTER DATA 依赖它发送数据；MASTER CLK 根据此发送时钟频率给 DSI-Slave 用于数据接收。这两个作用与 SLAVE CLK 和 SLAVE DATA 的功能相呼应。

PLL 生成的 Bit Clock 分别分频为 Byte Clock 和 Escape Clock ，给 DSI 主控使用。

见上图的 MASTER CLK 组件，它只具有 LP-TX 和 HS-TX 模块。对于 MIPI-DSI ，明确指定了 Clock Lane 只有发送时钟频率的能力。而 SLAVE CLK 组件，则是用于 MIPI-CSI ，需要接收来自摄像头的时钟频率。

MIPI-CSI 摄像头的内部也有 PLL ，可以让 SoC 发送 24MHz 时钟给它作为参考时钟，或它的底板设计有源晶振。换句话说，谁发送数据，谁就要发送时钟频率。

D-PHY的电平信号

D-PHY 的 Lane 被分为 LP 和 HS 模式。以下是它们的信号定义：

  • LP 模式：使用单端驱动，即一对差分信号 Dp/Dn 被作为两个常规的电平信号。它功耗低，但速率低（小于等于 10MHz ），信号电压幅度为 0~1.2V 。
  • HS 模式：使用低压差分信号，传输速率高，最大支持的传输速率取决于 D-PHY 的版本。但是功耗大，信号电压幅度为 100mV~300mV ，中心电平 200mV 。

这里重点说明一下 HS 模式下的差分信号。
差分信号的特点是抗干扰强，能有效抑制电磁干扰，以及时序定位精确。
在 HS 模式中使用差分信号传输数据，这时需要时钟信号为数据信号进行时序定位，采用双边沿 DDR 采集数据，见下图。

TCLKp 是表示一个时钟周期，UI 是表示 0.5 个时钟周期。

Escape Mode 的作用是什么？

  1. 进入 LPDT（Low-Power Data Transmission）模式，用于发送命令。在实际的使用中，用于给 DSI 屏幕发送 Panel-Init-Sequence 。
  2. 进入 ULPS（Ultra-Low Power State）模式，进入超低功耗模式。
  3. 发送 Reset-Trigger 到 DSI-Slave ，即发送 Reset 信号给 DSI-Slave 。
  4. 进入 HS Test 模式，测试 HS ，本文档不讲解这个。

    2. 信号 TxUlpsEsc 由 DSI 主控拉高（看蓝框，这是关键），目的是从 Escape Mode 进入 ULPS 模式。
    3. 信号 TxUlpsClk 由 DSI 主控拉高，表示请求 Clock Lane 进入 ULPS 模式。
    4. 当 Clock Lane 进入 ULPS 后，D-PHY 把信号 UlpsActiveNotClk 拉低，通知 DSI 主控 Clock Lane 已进入 ULPS 。
    5. 信号 UlpsActiveNot 由 D-PHY 拉低，表示 Data Lane 已进入 ULPS 。
  3. 退出 ULPS 模式：
    1. 信号 TxUlpsExit 和 TxUlpsClkExit 由 DSI 主控拉高并稍后拉低，请求 Lane(s) 退出 ULPS 。

    3. 当所有 Lane(s) 进入 LP-11 后，信号 TxUlpsExit 和 TxUlpsClkExit 由 DSI 主控拉低。

根据此图可知，MIPI-DSI 使用 DDR 采样数据，TCLKp 对应一个时钟周期，1UI 对应 0.5 个时钟周期，要求在上升沿或下降沿前，在 T_SETUP 期间准备好数据，且要在 T_HOLD 期间保持数据。

眼图由无数的信号叠加而来，在目前的行业标准中，以时钟为基准，使用 3bit 电平的波形叠加组合，以此形成眼图：

眼图中的信号抖动（Jitter）和噪声（Noise）的表现为：

  • 在横轴（时间轴）上，阴影区域的水平范围体现了时域抖动（Jitter）。假设眼高固定，眼宽越窄，即左右两边的阴影区域越宽，中间的空白区域越窄，则 T_SETUP 和 T_HOLD 时序越小，无法采样到数据。
  • 在纵轴（电压轴）上，阴影区域的垂直范围体现了电压噪声（Noise）。假设眼宽固定，眼高越矮，即上下两边的阴影区域越高，中间的空白区域越矮，则高低电平达不到接收端的 V_IHHS 和 V_ILHS（对应图 D-PHY_Signaling_and_Contention_Voltage_Levels ），无法采集到数据。

结合在一起理解，由于多次信号的叠加，如果：

  • 眼图的信息线变粗：出现模糊（Blur）现象，表示眼图越小，裕量越不充足，信号质量越差，接收端无法获取到数据。即阴影区域变宽，空白区域变窄。
  • 眼图的信息线变细：不会出现模糊（Blur）现象，表示眼图越大，裕量越充足，信号质量越好，接收端能很好地获取到数据。即阴影区域变窄，空白区域变宽。

在理想状态下，我们希望 T_SETUP 和 T_HOLD 各占 0.5UI 。但在物理实现中，因为硬件上的设计，如 SoC 控制器内部的链路、SoC 基板打线和走线、以及 PCB 走线等，数据线和时钟线之间出现偏移（偏差），从而使接收端错过最佳采样点。所以额外添加了一个名为 T_SKEW 的时序，由发送端对数据线和时钟线，通过添加/减少适当的 delay 进行校准（眼图眼宽加宽/收窄），从而找到相对最好的采样点。

知道 PLL 的 Fout 如何得出后，下一步就是了解 SSCG（Spread-spectrum Clock Generator），简称为“展频”，注意该组件在 PLL 结构图的左下部分。
什么是 SSCG ？由于信号的辐射主要是由于信号的能量过于集中在其载波频率位置，导致信号的能量在某一频点位置处的产生过大的辐射发射。因此为了进一步有效的降低 EMI 辐射，增加 SSC 机制，通过将一个时钟频率分散在一个频带范围内，将信号的能量分散，能够有效抑制 EMI 。
见下图，未开启 SSC 机制：幅度很大，且能量集中在一个点的红色波形（像一座山峰）；开启 SSC 机制：幅度较缓，且能量分散在一个频带范围内的绿色波形（像一个高原）。

开启展频需要以下参数：

  1. 扩展率（MR，Modulation Rate）：这是定义展频的范围，单位是百分比 “%” ，或是百万分比 “ppm” 。比如说时钟频率为 100MHz ，扩展率为 1% ，展频类型为向下展频，则展频的范围是 99MHz~100MHz 。
  2. 调制率（MF，Modulation frequency）：这是定义展频的频率，单位是 Hz 。比如说时钟频率为 100MHz ，调制率为 100KHz，扩展率为 1% ，展频类型为向下展频，则在 100MHz 内，它的每个 100KHz 内把时钟周期逐渐变为 99MHz ，再逐渐变回 100MHz（注意以上例图的下半部分）。
  3. 展频类型：分为向上展频、向下展频和中心展频。
    1. 向上展频：将频率向上展开一个频带范围，比如 100MHz ，扩展率为 1% ，则展频的范围是 100MHz~101MHz 。
    2. 向下展频：将频率向下展开一个频带范围，比如 100MHz ，扩展率为 1% ，则展频的范围是 99MHz~100MHz 。
    3. 中心展频：将频率上下展开一个频带范围，比如 100MHz ，扩展率为 1% ，则展频的范围是 99MHz~101MHz 。

对于 D-PHY ，SSCG 仅在传输频率为 2.5Gbps 及以上时使用。注意该组件在 PLL 结构图，SSCG_EN 、SEL_PF 、MFR 和 MRR 是控制 SSCG 的关键参数。其中：

  • SSCG_EN ：使能 SSCG 的信号
  • SEL_PF ：用于确定展频类型，默认为向下展频

协议层

协议层负责把原始数据打包为数据包并下发链路层，或把数据包解析拆包为原始数据并上发到应用层。

数据包

在 MIPI-DSI 规范中，像素数据和命令是根据自身的特性被协议层解析，去生成数据包。数据包分为短数据包和长数据包，见以下对它们的解释。

短数据包

固定 4 字节，原始数据占 2 字节，见下图。在 Video 模式下，在 LP 和 HS 可以用短数据包发送命令参数信息。
在实际使用中，比如发送 Panel-Init-Sequence ，有些 DCS 命令仅有 2 个字节，则打包为短数据包去发送；比如在显示图像时，当一行或一帧的像素数据传输完成，需要把 Hsync 信号和 Vsync 信号分别打包为短数据包去发送。

长数据包

长数据包的长度范围是 6~65541 字节。原始数据的最大长度取决于 2 个字节的 WC(Word Count) 域，即最长 65536-1 字节。见以下例图：

黑屏

以下是排查步骤：

  1. 检测背光有没有亮。如果没有亮，则：
    1. 检查 PWM 通道的对应 IO 是否已被其它设备占用和复用。
    2. 检查 PMIC 供电是否已给背光开启；检查是否有额外的供电 IO ，该 IO 是否已被占用，是否已经拉高。完成后可以把 PWM 通道的对应 IO 复用为 GPIO ，设置为高电平查看效果。
    3. 如果亮了，则把 IO 复用还原为 PWM 。把默认亮度等级调整为 230 左右，查看效果。试着把 PWM 通道的极性调转，再把 PWM 通道的频率加大。
  2. 根据硬件原理图，检查屏幕本身的供电和复位引脚是否正确，复位引脚是否被其它设备占用。
  3. 上电和复位时序是否满足规格书中定义的要求，可试着稍微加大一点裕量。
  4. 检查填写的 Panel-Init-Sequnce 是否和厂商提供的一致。
  5. 检查屏幕的像素时钟频率，检查 DPU/DE/LCDIF 输出的像素时钟频率，是否和在设备树节点 display-timing 中设置的一致。该问题的解决方法与 图像偏移/闪屏/花屏 类似。
  6. 检查 Bit Clock 时钟，尤其是 PLL for D-PHY 的参考时钟 pll_ref 和 PMS ，根据此去计算是否等于（或约等于）Bit Clock 。
  7. 检查 D-PHY 的时序参数，如 T_LPS 、T_HS-EXIT 和 T_HS-PREPARE 等，这些时序参数是否在屏幕规格书中定义的范围内。
  8. 此步骤仅限于速率在 1.5Gbps 以上，检查 Clock Lane 和 Data Lane(s) 之间的 skew ，在眼图找到最佳采样点。这是由硬件设计上导致的，使用示波器测量，调整 delay 。

整体软件框架

MIPI-DSI 驱动基于 DRM ，以 DRM 框架为主，drm_mipi_dsi 为辅。
先看 DRM 框架，如果是从零开始开发 MIPI-DSI 驱动，则直接针对 drm_encoder 和 drm_connector 开发。drm_encoder 负责 dsi-panel 的使能，drm_connector 负责从 dsi-panel 获取它的显示参数。

假设内核中已有 MIPI-DSI 驱动代码，一般来说它被封装为 drm_bridge 。我们实现一个简单的 drm_encoder ，来连接这个 drm_bridge 即可。另外，如果该 drm_bridge 的输出端不是下一个 drm_bridge ，则新建一个 drm_connector 。drm_bridge 负责 dsi-panel 的使能，drm_connector 负责从 dsi-panel 获取它的显示参数。

drm_mipi_dsi 是 DRM 框架内的一个子框架，它新增了两个类型，一个是 dsi_host ，另一个是 dsi_device 。额外定义了总线类型 bus_type（比如 platform 总线），叫作 “mipi_dsi_bus_type” ，用于连接各 DSI 总线的 dsi_device（mipi_dsi_device 和 mipi_dsi_driver）。当 dsi_host 在它自己的总线枚举外围设备时，如果找到一个可用的外围设备，则为它新建并登记 dsi_device 。dsi_host 内部有一系列的回调函数，集中在 mipi_dsi_host_ops ，定义了 ->attach() 、->detach() 和 ->transfer() 。它们的用处分别是：dsi_device 基本信息的回传；dsi_device 基本信息的移除；dsi_device 主动请求传输数据（多数用于请求发送 Panel-Init-Sequence）。

计算BitClock以及PLL的分频系数

至于第二步，根据 DSI的BitClock计算方法 了解基本的计算后，还需了解几个属性：MIPI_DSI_MODE_VIDEO_MBC 、min_hs_clock_multiple 和 mipi_dsi_multiple 。这些属性相对来说不太常见，但为了驱动的完整性吧，还是需要支持它们的。

  • MIPI_DSI_MODE_VIDEO_MBC ：用于 Video 模式，作用是把一个 pix_clk 时钟周期的像素，“一次性”在 DSI-Master 传输到 MIPI-Slave 。把像素字节按序划分给若干个 Lanes ，要求 bit_clk 满足的频率是一个 pix_clk 时钟周期完成一个像素的传输。
    计算方式： 比如：bpp=32 ，lanes=4 ，则 n=1 ，bit_clk_rate=pixclk * 1 * 8；意思是一个 pix_clk 时钟周期的像素，对应 DSIM 的 4 条 Lanes 传输一个像素需要 8 个时钟周期。bpp=32 ，lanes=2 ，则 n=2 ，bit_clk_rate=pixclk * 2 * 8；意思是一个 pix_clk 时钟周期的像素，对应 DSIM 的 2 条 Lanes 传输一个像素需要 16 个时钟周期。
  • min_hs_clock_multiple ：这个可能是 DSI-Master 要求的，也有可能是 DSI-Slave 要求的。当 bit_clk 频率小于 min_hs_clock_multiple pixclk 时生效。
  • mipi_dsi_multiple ：某些 D-PHY 要求 bit clock 频率必须是对某个基础频率（如 10MHz、20MHz）的整数倍。mipi_dsi_multiple 即为此对齐粒度（单位：Hz）。此处将 bit_clk_freq 向上对齐到最近的 mipi_dsi_multiple 的整数倍。

Atomic_Disable

进入 ModeSet 的 Commit 阶段，如果是 Enable->Disable ，或 Enable1->Enable2，则调用 drm_encoder 的回调函数 atomic_disable() ，需要做：

  1. 如果连接的外围设备是 Panel ，则回调它的 disable() ，详细见 Panel的Disable 。
  2. 把 DSI 主控关闭，包括 Data Lane(s) 。
  3. 关闭 Escape Clock 和 Byte Clock
  4. 关闭 PLL 。
  5. 如果连接的外围设备是 Panel ，则回调它的 unprepare() ，详细见 Panel的Unprepare 。
